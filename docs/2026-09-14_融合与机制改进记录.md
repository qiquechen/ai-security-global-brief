## 3. 采集机制改进

### 3.1 LLM-Native Crawler

新增 `Crawl4AIBackend`，在独立异步事件循环中维护一个共享 Chromium。不同采集线程共用后端，并通过异步锁串行操作浏览器，避免多线程直接共享浏览器对象。

静态链路仍是默认路径。只有来源明确配置为 fallback，且静态请求失败或正文不足 180 字符时，才对具体页面调用 Crawl4AI。`always` 仅适合必须渲染的 page 来源；`off` 不启用浏览器。

Crawl4AI 输出的原始 HTML 用于解析标题、发布日期和 canonical URL，裁剪后的 Markdown 用作正文。Crawl4AI 不调用 DeepSeek，主题判断仍由筛选阶段完成。

### 3.2 候选预过滤与可观测性

正文请求前新增或明确以下淘汰路径：

- `url_filtered`：URL 无效、入口自身、域名/路径白名单不符或文章 URL 正则不符。
- `hint_outside`：RSS/列表页已提供可靠日期，且该日期不在本次窗口。
- `blacklisted`：命中有效期内的语义剔除记录。
- `existing`：文章已经入库。
- `cached_outside`：历史观察已确认发布时间在本次窗口外。

三项新增重点指标会同时写入逐源日志、`crawl.source` 事件、最终控制台汇总和 `crawl.result` 事件。这样可以解释“raw 很高、eligible 为零”究竟是路径规则、日期还是黑名单导致。

### 3.3 日期缓存和二次检查

文章解析得到的可靠发布时间写入 `crawl_observations`。后续小时任务遇到无 Feed 日期的旧 URL，可以直接依据缓存跳过；历史扩窗覆盖该日期时仍允许重新进入候选。

正文抓取或浏览器跳转后可能产生新的 canonical URL，因此系统会再次执行允许域名、黑名单、已入库和窗口检查。数据库再通过 URL 唯一约束与正文哈希完成最终兜底。

## 4. 筛选与摘要机制改进

### 4.1 判定失败重试

批量语义筛选结束后，对调用失败或返回结构无效的条目统一重试一次。重试仍失败时保留 `classification_error`，日报准备失败，不会把调用异常当成“不收录”写入黑名单。

### 4.2 摘要事实核验

摘要流程现包含四层控制：

1. 模型响应必须正常结束，不能是长度截断。
2. 本地结构校验检查类型、500 字符上限、完整句尾和括号引号配对。
3. 确定性年份检查要求摘要中的年份能在标题、发布时间或原文中找到。
4. 第二次模型调用把摘要拆成 3—6 条事实断言，并为每条断言给出原文证据；存在 unsupported 断言即不通过。

首次不通过会携带问题重写一次，仍不合格则不缓存。缓存质量版本提升后，旧缓存自动失效。

### 4.3 单篇失败与分类配额

远端版本允许跳过单篇摘要失败，避免一篇问题材料拖垮整批。本轮增加后置配额校验：跳过后如果媒体或机构任一类别低于 `REPORT_MIN_PER_GROUP`，则停止生成报告；只有仍满足保底数量时才继续。这兼顾单篇容错和日报完整性。

## 5. 备份、告警与无人值守

- `prepare_daily.py` 在整理前调用 `backup_db.py`；备份失败会告警，但不阻断整理。
- 数据库备份使用 SQLite backup API，包含 WAL 中已提交事务，并通过临时文件原子替换同日备份，避免直接复制主文件造成不一致。
- 默认保留最近 `BACKUP_KEEP=14` 份日备份。
- 整理失败、发送失败和备份失败使用现有 SMTP 发送简短告警；`ALERT_RECIPIENT` 未配置时回退到普通收件人。
- 告警发送自身失败只写日志，不覆盖主流程原始退出码。
- 06:05 整理与 07:00 发送继续分离；发送阶段只读取就绪清单，不调用模型、不查询数据库、不现场生成文件。
