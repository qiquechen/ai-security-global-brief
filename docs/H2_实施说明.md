# H2 采集实施说明

更新日期：2026-09-14（北京时间）

## 1. 职责与数据边界

- 统一采集入口为 `python -m ai_digest.ingest.run`，`scripts/run_crawl.py` 调用同一入口。
- H2 负责来源发现、网页获取、正文抽取、发布时间解析、URL/正文去重和入库；不在采集层按关键词删除文章。
- H1 负责 DeepSeek 语义筛选、分类、重要度、摘要、排序、Word 生成和邮件交付。
- `articles` 保存正文；`crawl_observations` 缓存已确认的 URL 发布时间；`rejections` 保存有效期内的语义剔除记录。
- 正式日报窗口为北京时间 `[昨日06:00, 今日06:00)`；采集默认回看最近 2 天，历史补足最多向前扩展 30 天。

## 2. 完整采集流程

1. 加载 `config/sources.json`，校验来源 ID、采集方式、入口、允许域名、LNC 模式和文章 URL 正则。
2. 清理到期剔除记录，加载已入库 URL、有效黑名单以及 `crawl_observations` 中的已知日期。
3. 检查主线路、备用线路和旧 `PROXY` 兜底线路；只有明确的连接/代理故障才切换线路。
4. 如本轮存在 `lnc_mode=fallback/always` 的启用来源，启动一个共享的 Crawl4AI Chromium 后端。
5. 按 `INGEST_WORKERS` 并行处理不同来源；每个线程使用独立 `requests.Session`，同域名共享限速和 robots 缓存。
6. 从 RSS、Sitemap 或栏目页发现原始候选 URL；page 来源在静态发现失败或候选过少时可使用 Crawl4AI 增强发现。
7. 在请求正文前依次执行 URL 规范化、域名/路径/文章正则过滤、Feed 日期窗口过滤、黑名单过滤、已入库过滤和历史日期缓存过滤。
8. 对剩余候选按已知发布时间、AI 安全治理相关度和标题信息排序，再截取每源候选上限。
9. 正文默认先使用静态请求和 Trafilatura 抽取；静态失败或正文不足 180 字符时，配置为 fallback 的来源调用 Crawl4AI。
10. Crawl4AI 保留原始 HTML 用于标题、canonical URL 和发布日期解析，同时将渲染 DOM 清洗为裁剪后的 Markdown 正文。
11. 对最终 canonical URL 再检查黑名单、已入库、发布时间窗口和正文长度；通过后生成正文 SHA-256。
12. 主线程串行写入 SQLite，URL 唯一约束与正文指纹提供最后一道去重；随后关闭共享浏览器。

## 3. Crawl4AI / LLM-Native Crawler

| 模式 | 行为 |
| --- | --- |
| `off` | 只使用静态 HTTP 和 Trafilatura |
| `fallback` | 静态失败或正文过短时再启动浏览器抓取该页 |
| `always` | page 入口和文章正文都优先使用浏览器渲染 |

Crawl4AI 本身不调用 DeepSeek，也不做是否收录的语义判断。它只解决动态渲染、DOM 清洗和正文格式转换；结构化判断仍发生在 H1 阶段。

当前启用 fallback 的来源包括 Heritage、War on the Rocks、Guardian AI、日本时报 AI、独立报 AI 和 CDT。Heritage 使用 RSS 发现链接，再由 Crawl4AI 尝试恢复静态 403 的正文。

首次部署：

```powershell
pip install -r requirements.txt
crawl4ai-setup
```

可配置项：`INGEST_LNC_ENABLED`、`INGEST_LNC_START_TIMEOUT`、`INGEST_LNC_PAGE_TIMEOUT_MS`、`INGEST_LNC_RENDER_DELAY`、`INGEST_LNC_PRUNING_THRESHOLD` 和 `INGEST_LNC_SCAN_FULL_PAGE`。可用 `--disable-lnc` 做静态链路对照测试。

## 4. URL 过滤、黑名单与去重顺序

入口页面必须先访问，因为系统只有解析入口后才能知道候选 URL。候选 URL 一旦被发现，会在下载文章正文前过滤：

```text
入口发现
  → URL/域名/路径规则
  → Feed 日期窗口
  → 有效黑名单
  → 已入库 URL
  → 历史日期缓存
  → 正文抓取（静态 → 必要时 Crawl4AI）
  → canonical URL 再过滤
  → 发布时间/正文质量检查
  → SQLite URL + 正文指纹去重
```

DeepSeek 明确判定 `in_scope=false` 时，文章正文被删除，URL 写入剔除记录；默认保留 7 天。到期后允许再次采集，但先前删除的正文不会自动恢复。

## 5. 日志指标解释

| 字段 | 含义 |
| --- | --- |
| `raw` | 入口解析出的原始候选数 |
| `url_filtered` | 域名、路径、入口自身或文章 URL 正则淘汰数 |
| `hint_outside` | Feed/列表页已有可靠日期且不在本次窗口的数量 |
| `blacklisted` | 命中有效剔除记录的唯一 URL 数 |
| `existing` | 已入库或最终插入时发现重复的数量 |
| `cached_outside` | 历史日期缓存确认在窗口外、因此未重复下载的数量 |
| `eligible` | 预过滤后可进入候选排序的唯一 URL 数 |
| `fetched` | 实际尝试获取正文的数量 |
| `outside` / `missing_time` / `empty` | 正文解析后因时间、缺日期或正文质量淘汰 |
| `accepted` / `inserted` | 采集层通过 / 实际新增入库数量 |
| `lnc=成功/尝试` | Crawl4AI 得到足够正文 / 调用次数 |
| `recovered` | 静态链路失败或弱正文后由 Crawl4AI 恢复的数量 |

Crawl4AI 的绿色 `[FETCH]`、`[SCRAPE]`、`[COMPLETE]` 仅代表浏览器抓取和转换在技术上成功，不代表文章在时间窗内、符合主题、已入库或最终入选日报。

## 6. 当前来源状态

当前配置共 94 项，启用 76 项、停用 18 项；启用源每轮候选上限之和为 1820。类型、地区、方式、逐源入口和停用原因统一以 [源清单统计.md](源清单统计.md) 为准，该文件由以下命令生成：

```powershell
python scripts/count_sources.py
python scripts/gen_source_docs.py
```

启用不等于每轮有新增，入口可访问也不等于正文可访问。恢复停用来源前必须验证入口、robots、候选日期、正文和 canonical URL。

## 7. 运行与验证

```powershell
python -m ai_digest.ingest.run --validate-only
python -m ai_digest.ingest.run --check-connectivity
python scripts/run_crawl.py
python -m ai_digest.ingest.run --source guardian_ai --days 2 --max-per-source 3 --workers 1
python -m ai_digest.ingest.run --days 2 --disable-lnc
python -m unittest discover -s tests
```

Windows 采集任务每小时 `:05` 执行，并在每日 `05:55` 补抓；06:05 整理，07:00 仅发送已经准备好的批次。

## 8. 已知边界

- robots 明确禁止时不会绕过；Crawl4AI 也不能作为绕过 robots、付费墙或授权限制的工具。
- 94 项配置不是 94 个每日活跃来源，机构站点更新频率通常低于媒体。
- 默认两天窗口、历史去重、剔除记录和 DeepSeek 语义筛选都会降低最终日报数量，这是质量控制而非抓取失败。
- 入口页面可发现的历史范围有限，因此最多回溯 30 天也不保证满足分类配额。
- 来源恢复率、最终召回率和日报准确率应以持续生产日志与人工抽样为准。
