# H2采集实施说明

## 已冻结的融合边界

- H2入口固定为 `python -m ai_digest.ingest.run`，H1的 `scripts/run_crawl.py` 直接调用同一个 `main()`。
- H2只调用 `ai_digest.db.init_db()`、`connect()` 和 `insert_article()`，未修改H1定义的 `articles` 表结构。
- 入库必填字段为 `source_id / url / title / published_at / text`，同时写入UTC抓取时间和正文哈希。
- H2不做关键词或A-H语义删选；判定、摘要、排序、DOCX与发信继续由H1负责。
- 正式日报读取北京时间 `[昨日06:00, 今日06:00)`；`--hours` 仅用于联调旧样本。

## 采集规则

- 只访问 `config/sources.json` 中启用且属于 `allowed_domains` 的地址。
- 默认拒绝非HTTP(S)、跨域重定向、搜索/筛选参数页和显式排除的栏目页。
- 默认遵守 `robots.txt`；robots不可用时采用fail-closed，不越权抓取。
- 每域请求间隔默认0.3秒，超时25秒，失败重试2次，响应上限4MiB。
- 发布时间统一为UTC ISO 8601；缺少可靠发布时间、正文不足180字符或超出窗口的候选不入库。
- 已入库URL在正文请求前跳过；数据库URL唯一约束作为最终兜底。

## 当前来源状态

融合清单首批17项，其中15项启用。美国商务部和RAND因访问合规问题默认禁用。
40+来源的扩容属于后续逐站适配工作，不影响当前H1/H2最小闭环联调。

```powershell
python -m ai_digest.ingest.run --source aisi_uk --days 60 --max-per-source 3 --export data/sample_articles.jsonl

```
