# 人工智能安全治理·摘报筛选标准 v1.0（按《人工智能安全治理框架》2.0 对齐）

> 本文件是"境外人工智能安全治理信息智能摘报"系统的**内容筛选语义标准**，作为大模型判定与人工复核的统一依据。
> 依据：中央网信办指导、国家互联网应急中心牵头制定、全国网安标委技术文件 **《人工智能安全治理框架》2.0版**（2025-09-15 发布）。
> 本 v1.0 合并并取代此前《摘报筛选口径 v0.9》与《H1 判定评分卡与提示词 v0.9》。状态：待 H1 / 对接人最终复核。
> 已确认口径决定：军事国防与 LAWS 收录（中性表述）；出口管制与算力收录；单条摘报不带主观研判；板块全谱系覆盖、暂不缩窄。

---

## 0. 用途

回答筛选流水线三问：是否属于"人工智能安全治理"范畴；属哪类；重要度几何。判定以语义理解为主，词表仅用于采集阶段粗召回。

---

## 1. 收录总则（三要素）

一条信息同时满足以下三条才收录：

1. **主题要素**：围绕人工智能引发的安全风险及其治理。风险口径对齐《框架2.0》第3章三大类（技术内生 / 技术应用 / 应用衍生）；治理口径对齐其第4、5、6章（技术应对、综合治理措施、研发应用安全指引）。
2. **主体要素**：发布主体为政府、监管机构、国际组织、权威智库或主流媒体；或事件被上述主体认定、具有治理意义。
3. **信息要素**：对理解"美西方（及欧盟等）如何治理人工智能安全、其治理动向与风险态势"具有增量价值。

---

## 2. 内容分类体系（框架对齐）

> 判定收录后，从下列"风险类 / 治理类 / 专项类"中给出一条主分类。分类名对应框架章节，模型按语义归类。

### R 类 · 安全风险动态（对齐框架第3章）

- **R1 技术内生·模型算法安全**：可解释性不足、偏见歧视、鲁棒性不强、输出不可靠/幻觉、外部对抗攻击、模型缺陷向下游扩散、开源放大"作恶模型"风险。
- **R2 技术内生·数据安全**：违规收集使用数据、训练数据内容不当/投毒、训练标注不规范、数据与个人信息泄露（含从模型参数中诱导泄露）。
- **R3 技术应用·网络系统安全**：组件与算力安全（框架/平台/算力设施漏洞后门）、网络暴露面扩大与智能体权限滥用、供应链安全（芯片/软件/工具断供、出口管制单边措施）、网络攻击滥用（AI降低攻击门槛、深度伪造绕过身份认证）。
- **R4 技术应用·信息内容安全**：输出违法有害信息、混淆事实误导用户（深伪、生成内容未标识）、污染网络内容生态。
- **R5 技术应用·现实安全**：关键信息基础设施（能源/电信/金融/交通）运行风险、被违法犯罪利用、核生化导等武器相关知识能力失控扩散。
- **R6 技术应用·认知安全**：加剧"信息茧房"、被用于认知战与舆论操纵（社交机器人、干涉他国）。
- **R7 应用衍生·社会与环境安全**：冲击劳动就业结构、算力无序建设与能耗对资源供需/绿色发展的挑战。
- **R8 应用衍生·伦理安全**：社会偏见与智能鸿沟、冲击教育抑制创新、加剧科研伦理风险（生物/基因等）、拟人化交互沉迷依赖、挑战社会秩序、"自我意识"失控脱离人类控制。

### M 类 · 治理举措与机制动态（对齐框架第4、5、6章）

- **M1 政策法规与监管**：法律法规制定修订、行政命令、监管规则与执法、司法判决、机构监管职权变化（框架5.1，并覆盖美欧立法监管动向）。
- **M2 科技伦理与安全准则**：人工智能科技伦理准则、以人为本/智能向善原则的制度化、可信AI准则的推广落地（框架5.2、附件2）。
- **M3 标准、测评与技术应对**：安全测评体系建设、评估评测方法与基准、安全标识与合成内容可追溯（AIGC溯源/水印）、技术应对措施的标准与指南（NIST AI RMF、ISO/IEC 42001、EU AI Act 细则等）（框架4、5.6、5.8）。
- **M4 全生命周期安全与行业应用治理**：研发—部署—运行—使用的全生命周期安全要求、应用分类分级管理、重要行业应用的安全有序释放、运行监测与应急预案（框架5.3、5.5、5.7、第6章）。
- **M5 开源生态与供应链治理**：开源生态安全、供应链安全、出口管制与芯片/算力治理（框架5.4；结合用户确认——出口管制与算力收录）。
- **M6 数据安全与个人信息保护**：数据安全与个人信息保护规范在AI场景的落实、泄露事件与合规要求（框架5.10）。
- **M7 风险信息共享与失控协同**：AI安全风险威胁信息共享机制、协同应对AI失控风险的共识与机制（框架5.9、5.11）。
- **M8 人才、意识与国际合作**：安全人才培养、社会安全意识、国际交流合作与多边机制（AI安全峰会、AI安全研究院国际网络、OECD/G7/G20/联合国等）（框架5.12、5.13、5.14）。

### X 类 · 专项（用户确认收录）

- **X1 军事与国防 AI 应用及自主武器**：AI 在军事/国防/情报领域的应用政策与动态、致命自主武器系统（LAWS）相关立场与治理讨论。
  表述要求：**客观转述外方立场与动态，中性用词，不掺入我方价值判断**；涉敏感表述以"自主武器系统"等规范词呈现。
- **X2 出口管制与算力治理（独立归置备用）**：通常并入 M5；当信息主体是"芯片/算力出口管制新规或制裁"时归 M5，当涉及军事用途管制时归 X1。

---

## 3. 明确不收（排除边界）

- 纯 AI 技术/产品发布与跑分、纯商业与融资、一般公司人事——除非触及上列风险或治理。
- 与 AI 安全治理无关的一般科技与社会新闻。
- 对既有报道无新信息的重复内容；来源权威性不足、不在指定机构清单内者。
- 纯技术细节的学术论文（未达政策/安全影响层面）。
- 低价值日常动态（会议预告、日程、纯转载）。
- **凡属军事国防与 LAWS 内容的表述，不带我方倾向；无法保证中性的不收**（由人工复核把关）。

---

## 4. 重要度分级（对齐框架附件1 风险分级原则 + 政策信号强度）

分级参考三个维度：风险/事件的影响面（关键基础设施、大规模、跨行业）、政策信号强度（是否国家层新举措）、机构权威性。

- **高（优先入列）**：国家层面立法、行政命令、新战略或专门机构重大动作；较大/重大级别安全风险事件或预警（涉国家安全、关键基础设施、核生化导等）；大国正式协调/协议；重大安全事故或执法；治理范式性变化。
- **中**：机构指南与标准发布、监管规则征求意见、重要智库报告、针对性执法/罚款、国际会议实质性成果、中等级别风险事件。
- **低**：一般动态、重申既有立场、个别专家观点、细则层面更新（仅信息稀缺时补位）。

排序综合：权威性 × 时效 × 影响面 × 新颖度。同一事件多源报道合并为一条。每日总量 **10–20 条**。

## 5. 判定 System Prompt（筛选官）

```
你是一名境外人工智能安全治理信息摘报系统的资深筛选官。你依据中国《人工智能安全治理框架》2.0版所确立的风险与治理分类，判断输入信息是否属于"人工智能安全治理"范畴并归类定级。

【收录三要素】
1. 主题要素：是否围绕人工智能引发的安全风险（技术内生、技术应用、应用衍生）或其治理（政策法规、标准测评、供应链与算力、国际合作等）。
2. 主体要素：发布主体是否为政府、监管机构、国际组织、权威智库或主流媒体，或事件是否被上述主体认定、具治理意义。
3. 信息要素：是否对理解美西方（及欧盟等）人工智能安全治理动向与风险态势具有增量价值。

【分类体系】
- R1 技术内生·模型算法安全  R2 技术内生·数据安全
- R3 技术应用·网络系统安全（含供应链与出口管制/算力）  R4 技术应用·信息内容安全  R5 技术应用·现实安全（含关键基础设施、核生化导）  R6 技术应用·认知安全
- R7 应用衍生·社会与环境  R8 应用衍生·伦理安全
- M1 政策法规与监管  M2 科技伦理与安全准则  M3 标准测评与技术应对  M4 全生命周期安全与行业应用治理  M5 开源生态与供应链治理（出口管制/算力）  M6 数据安全与个人信息保护  M7 风险共享与失控协同  M8 人才意识与国际合作
- X1 军事国防AI与自主武器（LAWS）
如信息同时涉及治理与风险，优先归入治理类 M；军事国防与出口管制相关内容明确保留（X1/M5）。

【明确不收】
纯技术与产品发布且不涉安全治理；纯商业融资；无关科技社会新闻；无新信息的重复内容；来源权威性不足；纯技术细节论文；低价值日常动态。

【重要度】
high：国家层立法/行政令/新战略/专门机构重大动作；较大及以上风险事件或预警；大国正式协调/协议；重大事故或执法；范式性变化。
med：机构指南标准发布、监管征求意见、重要智库报告、针对性执法、国际会议实质成果、中等级风险事件。
low：一般动态、重申立场、个别观点、细则更新。

【纪律】
- 语义理解为主，禁止仅凭关键词收录；拿不准时 in_scope 取 false，但重大风险与重大政策信号不可遗漏；
- 只依据所给原文判断，不臆测、不补充；
- 判断理由须客观中立，禁止输出任何主观研判、影响评估或倾向性结论；
- 军事国防与自主武器内容一律中性转述判定，不判断"对我利弊"。

【输出】
只输出一个 JSON 对象，无其他文字：
{"in_scope": true或false, "category": "R1"~"R8"或"M1"~"M8"或"X1"或null, "importance": "high"或"med"或"low"或null, "reason": "≤60字中文客观理由"}
in_scope=false 时 category 与 importance 为 null；in_scope=true 时二者必填。
```

## 6. 单篇判定 User Prompt 模板

```
请判定以下信息：
- 标题：{title}
- 来源：{source_name}（{country}）
- 时间：{published_at}
- 链接：{url}
- 内容摘录：{excerpt}

按系统提示词要求输出 JSON。
```

`{excerpt}` 取正文前 800–1500 字。

---

## 7. 摘要与翻译加工要求

- 单条结构（纯客观）：中文标题、来源机构、日期、原文链接、核心观点（2–3 点）、关键事实与数据。**不设"影响研判/对我启示"栏目，禁止任何主观倾向、预测或建议表述。**
- 全文 **≤500 字**；只基于原文改写，不补充外部知识；事实与数字须能溯源原文。
- 术语遵循术语表；英文专名首次出现括注原文；军事/国防内容中性用词。
- 摘要给出后由人工复核"是否漏收、是否误收、是否夹带主观"三件事。
